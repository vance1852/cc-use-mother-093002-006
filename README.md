# 跨境邮政路由与责任编排平台

本仓库在「数字贸易协作基础服务」的稳定边界（角色权限、请求幂等、SQLite 事务、哈希串联审计）之上，实现跨境邮政中转的路由与责任编排：接收包裹事实、申报及证明版本、来源和目的辖区规则、服务承诺、口岸、运输区段、容器容量与交接资格，生成带理由的中转方案，并在合包、拆包、封袋、转运、查验、改道和签收全过程中保留包裹与容器的双向谱系。

## 目录

- src/digital_trade_foundation/：基础服务——主体、场所、资料、权限、幂等、审计链与 HTTP 边界；
- src/postal_routing/：邮政路由领域——规则引擎、方案生成、原子运力预留、容器谱系、查验与责任、可披露查询；
- tests/：基础服务与邮政路由的规则、事务、接口和端到端验收测试。

## 环境

- Linux
- Python 3.11 或更高版本
- 运行时仅使用 Python 标准库和 SQLite

## 测试

    PYTHONPATH=src python3 -m unittest discover -s tests -v

## 构建检查

    python3 -m compileall -q src tests

## 离线验收

    PYTHONPATH=src python3 -m digital_trade_foundation.acceptance
    PYTHONPATH=src python3 -m postal_routing.acceptance

邮政验收会在临时 SQLite 数据库中跑通：建网（口岸/区段/承诺/规则）→ 生成带理由的方案与稳定优先级备用路线 → 重放不多占运力 → 合包封袋发运 → 模拟进程重启后在途容器与候补路线保持一致 → 承运交接确认 → 口岸查验与节点责任 → 拆包签收（完成后不可改写）→ 口岸关闭正向级联改道 → 超时责任扫描幂等 → 客服可披露视图 → 审计链校验。成功时输出一行 status 为 ok 的 JSON 并以退出码 0 结束。

## HTTP 服务

    PYTHONPATH=src python3 -m postal_routing.api --database postal.sqlite3 --host 127.0.0.1 --port 8081

健康检查使用 GET /health。写入接口通过 X-Actor-Id 标识操作者；基础登记接口（/organizations、/actors 等）与邮政接口（/postal/...）由同一进程提供，重启后 SQLite 中的业务状态、谱系与审计历史继续保留。

## 领域规则摘要

- 方案生成：以来源区域可用口岸为起点、目的国口岸为终点枚举候选路径，按（段数、优先级和、区段编号）稳定排序，首选即主方案，其余为备用路线；禁限运品、申报价值门槛、证明文件等辖区规则逐条评估并写入理由。
- 容量预留：主方案每段运力在同一 IMMEDIATE 事务内校验并写入预留；request_id 幂等，重放事件不会多占资源；备用路线只在改道时才占用容量。
- 谱系与不可改写：合包、封袋、发运、到达、查验、放行、拆包、签收均追加 parcel↔container 双向谱系事件；已签收包裹的申报、方案与交接记录不可重写，规则或证明变化只影响尚未完成且剩余路径确实命中的对象。
- 责任：查验从容器所在节点开启责任记录；超时扫描按包裹当前位置把责任归于节点或承运方，确定性编号保证重放与重启后不重复开立。
- 披露：节点、承运方、合规各自确认交接；客服（support 角色）只能查询可披露的状态与原因，无法读取方案、规则与责任明细。
